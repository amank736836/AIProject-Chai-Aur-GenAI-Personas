# BUG-013 — 500 responses leak provider error text and environment-variable names

| Field | Value |
|---|---|
| **Bug ID** | BUG-013 |
| **Title** | 500 responses leak provider error text and environment-variable names |
| **Severity** | Medium |
| **Priority** | P1 |
| **Feature** | FEAT-012, FEAT-011 |
| **Environment** | commit `d24eb41`, dev server, RUN-2026-001 |
| **Preconditions** | Provider call fails for a reason that is not classified as a rate limit (missing key, wrong key, network error) |
| **Steps to Reproduce** | 1. `curl -X POST http://localhost:3000/api/chat -H 'Content-Type: application/json' -d '{"message":"hello","persona":"hitesh"}'` (no `GROQ_API_KEY`) 2. Inspect the JSON body |
| **Expected** | A generic message such as `{"error":"The assistant is temporarily unavailable."}` |
| **Actual** | `500 {"error":"Groq API key is missing. Pass it using the 'apiKey' parameter or the GROQ_API_KEY environment variable."}` — the provider SDK's internal message, including the operator's environment-variable name, is returned verbatim to anonymous callers |
| **Reproducible** | YES |
| **Evidence** | [`../../evidence/api-responses/TC-005-chat-provider-error.json`](../../evidence/api-responses/TC-005-chat-provider-error.json), [`TC-068`](../../evidence/api-responses/TC-068-security-provider-error.json) |
| **Root Cause** | `src/app/api/chat/route.ts:184-188` — the fallback branch returns `msg` (the raw `Error.message`) instead of a curated message; the same pattern exists in `lib/llm.js:20` (`"All LLM providers failed: " + err2?.message`) |
| **Fix** | Return a generic message to clients, keep the detail in `console.error`; optionally add an error id for support correlation |
| **Regression Test** | TC-005, TC-068 (automated, `{ todo: "BUG-013" }`) |
| **Status** | OPEN |
