# BUG-010 — Malformed JSON body → unhandled 500 instead of 400

| Field | Value |
|---|---|
| **Bug ID** | BUG-010 |
| **Title** | Malformed JSON body → unhandled 500 instead of 400 |
| **Severity** | Medium |
| **Priority** | P1 |
| **Feature** | FEAT-012 (error handling) |
| **Environment** | commit `d24eb41`, dev server, RUN-2026-001 |
| **Preconditions** | none |
| **Steps to Reproduce** | 1. `curl -X POST http://localhost:3000/api/chat -H 'Content-Type: application/json' -d 'not-json' -w '\nHTTP %{http_code}\n'` 2. Repeat for `/api/create-persona` and `/api/fetch-image` |
| **Expected** | `400` with a JSON body such as `{"error":"Invalid JSON body"}` |
| **Actual** | `HTTP 500` with an **empty** body on all three routes: `await req.json()` on line 30/37/5 sits outside any try/catch, so the `SyntaxError` escapes the handler |
| **Reproducible** | YES (deterministic on all three routes) |
| **Evidence** | [`../../evidence/api-responses/TC-002-chat-invalid-json.txt`](../../evidence/api-responses/TC-002-chat-invalid-json.txt), [`TC-016`](../../evidence/api-responses/TC-016-create-persona-invalid-json.txt), [`TC-024`](../../evidence/api-responses/TC-024-fetch-image-invalid-json.txt) |
| **Root Cause** | No request-body guard; the JSON parse happens before the validation branch |
| **Fix** | Wrap the parse in try/catch and return `400 {"error":"Invalid JSON body"}`; consider a shared `parseJsonBody()` helper for all three routes |
| **Regression Test** | TC-002, TC-016, TC-024 (automated, `{ todo: "BUG-010" }`) |
| **Status** | OPEN |
