# BUG-012 — Persona creation reports success when tone generation failed

| Field | Value |
|---|---|
| **Bug ID** | BUG-012 |
| **Title** | Persona creation reports success when tone generation failed |
| **Severity** | High |
| **Priority** | P1 |
| **Feature** | FEAT-004 |
| **Environment** | commit `d24eb41`, dev server without provider keys, RUN-2026-001 |
| **Preconditions** | Provider unavailable/misconfigured, or rate-limited |
| **Steps to Reproduce** | 1. `curl -X POST http://localhost:3000/api/create-persona -H 'Content-Type: application/json' -d '{"name":"Harness Probe"}'` (no provider keys) 2. Inspect status, body and the `personaData-harness-probe` cookie |
| **Expected** | An error status, or a clear degraded result — never `success:true` for a persona with no tone |
| **Actual** | `200 {"success":true,"tone":""}` and the cookie persists `{"name":"Harness Probe","tone":""}`; the UI then waits 2 s and enables chat with a persona that has no style (interacts with BUG-006) |
| **Reproducible** | YES |
| **Evidence** | [`../../evidence/api-responses/TC-017-create-persona-silent-failure.json`](../../evidence/api-responses/TC-017-create-persona-silent-failure.json), [`../../evidence/api-responses/TC-018-create-persona-cookie.txt`](../../evidence/api-responses/TC-018-create-persona-cookie.txt) |
| **Root Cause** | `src/app/api/create-persona/route.ts:60-66` — `try { tone = await getLLMResponse(prompt) } catch (e) { tone = "" }`: the failure is swallowed and the empty string is treated as a valid tone |
| **Fix** | Return `502`/`503` with an actionable message when the tone cannot be generated, or return a `degraded: true` flag; the client should not unlock the chat input for an empty tone |
| **Regression Test** | TC-017 (automated, `{ todo: "BUG-012" }`), TC-051 (manual UI) |
| **Status** | OPEN |
