# BUG-007 — `@handle` persona tone is never found (cookie key mismatch)

| Field | Value |
|---|---|
| **Bug ID** | BUG-007 |
| **Title** | `@handle` persona tone is never found (cookie key mismatch) |
| **Severity** | High |
| **Priority** | P1 |
| **Feature** | FEAT-004 |
| **Environment** | commit `d24eb41`, Node v22.22.3, RUN-2026-001 |
| **Preconditions** | A persona created from a handle (`@amank736836`) |
| **Steps to Reproduce** | 1. `node harness/automation/utilities/repro-findings.mjs` (BUG-007 line) 2. Compare the cookie written by `/api/create-persona` (`personaData-@amank736836`, see TC-018 pattern) with the lookup key used in `buildPrompt` after `chat/route.ts:29-31` strips `@` |
| **Expected** | The tone generated for `@handle` personas is applied when chatting with them |
| **Actual** | Lookup misses (`@handle tone found after chat route strips "@": false`) → generic empty template, same symptom as BUG-006 |
| **Reproducible** | YES (deterministic) |
| **Evidence** | [`../../evidence/api-responses/repro-findings.txt`](../../evidence/api-responses/repro-findings.txt), `../test-results/latest/raw/unit-tests.log` (TC-033) |
| **Root Cause** | `create-persona/route.ts:41` builds the cookie name from the raw name (`personaData-@user`), while `chat/route.ts:29-31` strips the leading `@` before calling `buildPrompt`, which then looks for `personaData-user` |
| **Fix** | Strip the `@` consistently when the cookie name is created (or stop stripping it in the chat route); add a single `personaCookieKey(name)` helper used by both routes |
