# BUG-004 — Prompt transparency never receives data

| Field | Value |
|---|---|
| Bug ID | BUG-004 |
| Title | Prompt transparency never receives data (`prompt` is never returned; `debugPrompt` ignored) |
| Severity | Medium |
| Priority | P1 |
| Feature | FEAT-007 (prompt transparency), FEAT-010 |
| Environment | commit `d24eb41`, source review + response captures (RUN-2026-001) |
| Preconditions | none |
| Steps to Reproduce | 1. `curl -s -X POST http://localhost:3000/api/chat -H 'Content-Type: application/json' -d '{"message":"hi","persona":"hitesh","debugPrompt":true}'` (with credentials) 2. Inspect the JSON keys 3. Or read `page.tsx:220` — the `debugPrompt` flag is never sent, and `PromptDisplay.tsx` receives `prompt=""` |
| Expected | As the README claims, the user can display the full prompt used for the reply |
| Actual | No code path returns a `prompt` field from `/api/chat`, the client never sends `debugPrompt`, and `PromptDisplay` renders nothing (the "Show Prompt" toggle exists in the UI but is always empty). Feature is present in the README, absent in behaviour |
| Reproducible | YES (static, deterministic) |
| Evidence | code references `src/app/api/chat/route.ts` (no `prompt` in any response), `src/app/page.tsx:220`, `src/app/components/PromptDisplay.tsx`; cases TC-047, TC-043 |
| Root Cause | The feature was scaffolded on the client and documented, but the server never returned the built prompt and the client never requested it. `getHistoryFromCookies`/`buildPrompt` results are only used internally |
| Fix | Either return `prompt` (behind `debugPrompt === true`, truncated) in the chat response and pass it to `PromptDisplay`, or remove the UI + README claim. Given prompt-injection exposure (TC-071), returning it to the requester only is acceptable |
| Regression Test | TC-047 (manual/static FAIL), TC-043 (documents the missing client fetch); automate with credentials once a `prompt` field exists |
| Status | OPEN |
