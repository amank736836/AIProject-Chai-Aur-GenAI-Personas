# BUG-016 — Persona name is interpolated into a `RegExp` unescaped

| Field | Value |
|---|---|
| **Bug ID** | BUG-016 |
| **Title** | Persona name is interpolated into a `RegExp` unescaped |
| **Severity** | Low |
| **Priority** | P2 |
| **Feature** | FEAT-004, FEAT-006 |
| **Environment** | commit `d24eb41`, code review of `src/app/api/chat/route.ts:23` and `create-persona/route.ts:46` |
| **Preconditions** | none |
| **Steps to Reproduce** | 1. Read `src/app/api/chat/route.ts:19-25`: `cookieName` derives from `customName`, then `new RegExp(`${cookieName}=([^;]+)`)` 2. Send `persona=*.` / `customName=".*"` (or any regex metacharacters) and observe that the regex matches unintended cookies |
| **Expected** | Values inserted into a regular expression are escaped (`escapeRegExp`) or the lookup does not use a regex at all |
| **Actual** | Metacharacters are interpreted (`.*` matches any character sequence), so a crafted persona name can make the history lookup read a different cookie from the caller's own jar; a pathological pattern could also cause excessive backtracking |
| **Reproducible** | YES by inspection; impact is limited to the caller's own cookie jar (no cross-user data exists) |
| **Evidence** | code reference `src/app/api/chat/route.ts:19-25`; related evidence `TC-019` (same input reaching cookie names) |
| **Root Cause** | Building a regex from user input without escaping (and without validating the name) |
| **Fix** | Parse `Cookie` into a `Map` once and look up by exact key; if a regex stays necessary, escape the interpolated value |
| **Regression Test** | TC-070 (static/documentation guard; runtime assertion needs provider credentials) |
| **Status** | OPEN |
