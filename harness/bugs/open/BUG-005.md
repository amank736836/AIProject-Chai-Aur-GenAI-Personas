# BUG-005 — Client fetches `/data/*-tone.json` (404) and discards the result

| Field | Value |
|---|---|
| Bug ID | BUG-005 |
| Title | Client fetches `/data/*-tone.json` which the server never exposes (404) and discards the result |
| Severity | Low |
| Priority | P2 |
| Feature | FEAT-010 (tone data & prompt building) |
| Environment | commit `d24eb41`, dev server, RUN-2026-001 |
| Preconditions | none |
| Steps to Reproduce | 1. `curl -s -o /dev/null -w '%{http_code}\n' http://localhost:3000/data/hitesh-tone.json` → `404` 2. Read `page.tsx:120-165` (`fetch(\`/data/${persona}-tone.json\`)` inside an effect) |
| Expected | Either the tone data is served from `/data/…` (it lives in the repo's `data/` folder, outside `public/`) or the client does not fetch it |
| Actual | Every persona switch issues a request that 404s; the JSON is parsed from `res.json()` only on success, and the resulting `personaTone` state is never rendered (unused variable), so the whole path is dead work plus a console error |
| Reproducible | YES |
| Evidence | [`../../evidence/api-responses/TC-043-data-json.txt`](../../evidence/api-responses/TC-043-data-json.txt), [`../../evidence/performance/performance-latency.md`](../../evidence/performance/performance-latency.md) (probe: `GET /data/hitesh-tone.json` → 404) |
| Root Cause | Tone data is server-only (read with `fs` in `chat/route.ts`), but `page.tsx` tries to fetch it over HTTP from a path that is not served; the fetched value is then unused (dead code, see also the `no-unused-vars` lint warnings) |
| Fix | Delete the client fetch and the unused state (server already builds the prompt), or move the tone files into `public/data/` if the client really needs them |
| Regression Test | TC-043 (automated, `{ todo: "BUG-005" }`) |
| Status | OPEN |
