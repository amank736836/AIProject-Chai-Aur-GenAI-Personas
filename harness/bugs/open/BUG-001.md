# BUG-001 — `/api/clear-history` is called by the UI but does not exist (404)

| Field | Value |
|---|---|
| Bug ID | BUG-001 |
| Title | `/api/clear-history` is called by the UI but does not exist (404) |
| Severity | Medium |
| Priority | P1 |
| Feature | FEAT-013 (chat clearing on unload), FEAT-006 (persistence) |
| Environment | commit `d24eb41`, dev server `next dev` on `http://localhost:3000`, RUN-2026-001 |
| Preconditions | none |
| Steps to Reproduce | 1. `curl -si -X POST http://localhost:3000/api/clear-history \| head -3` 2. Or open the app, send one message, then reload the page and check the network tab |
| Expected | Either the endpoint exists and clears the persona history cookie, or the UI does not call it (and a local cookie reset is used instead) |
| Actual | `HTTP/1.1 404 Not Found` — `page.tsx:134-153` fires `navigator.sendBeacon("/api/clear-history", …)` on `beforeunload`, so every unload produces a silent 404 in the browser console. Because the beacon never succeeds, "clearing" is purely client-side and the storage cookies survive |
| Reproducible | YES (deterministic) |
| Evidence | [`../../evidence/api-responses/TC-054-clear-history.json`](../../evidence/api-responses/TC-054-clear-history.json), [`../../test-results/latest/raw/api-tests.log`](../../test-results/latest/raw/api-tests.log) (TC-054) |
| Root Cause | The route handler was never implemented (`src/app/api/clear-history/` does not exist) while the client code and the README both reference it. Nothing tests it, so the gap was invisible |
| Fix | Either add `src/app/api/clear-history/route.ts` (expire `chatHistory-*` / `personaData-*` cookies with `Max-Age=0`) or remove the beacon and clear the cookies in the client (`document.cookie = "…; Max-Age=0"`). Decide the intended UX first: BR-011 says the visible chat clears but history is kept for the same persona, so the beacon is arguably the wrong action |
| Regression Test | TC-054 (automated, `{ todo: "BUG-001" }`) |
| Status | OPEN |
