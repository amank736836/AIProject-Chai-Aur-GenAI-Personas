# BUG-003 — `btoa()` crashes on non-Latin1 chat text, so the cookie is never written

| Field | Value |
|---|---|
| Bug ID | BUG-003 |
| Title | `btoa()` crashes on non-Latin1 chat text, so the cookie is never written |
| Severity | High |
| Priority | P1 |
| Feature | FEAT-006 |
| Environment | commit `d24eb41`, Node v22.22.3 unit harness (identical in browsers: `btoa` is specced to throw above U+00FF) |
| Preconditions | A message containing Devanagari, emoji or any character above U+00FF |
| Steps to Reproduce | 1. `node harness/automation/utilities/repro-findings.mjs` (BUG-003 line) 2. Or unit: `await saveChatToCookieWithData([{ role: "user", text: "नमस्ते" }])` 3. Or in a browser: type Hindi text, reload |
| Expected | The transcript is saved (or the failure is caught and surfaced) |
| Actual | `DOMException: InvalidCharacterError` from `btoa("नमस्ते")` propagates out of the save path; no cookie is written and the exception is not caught anywhere in the call chain |
| Reproducible | YES (deterministic) |
| Evidence | [`../../test-results/latest/raw/unit-tests.log`](../../test-results/latest/raw/unit-tests.log) (TC-057 `# TODO`), [`../../evidence/api-responses/repro-findings.txt`](../../evidence/api-responses/repro-findings.txt) |
| Root Cause | `CookieManager.ts` line ~44 uses `btoa(...)` on JSON that may contain arbitrary user text; `btoa` only accepts code points ≤ U+00FF |
| Fix | Encode with `encodeURIComponent` + `escape`-based helper, or `TextEncoder` → base64, or store `encodeURIComponent(JSON.stringify(chat))` directly. Add the Unicode case to the cookie tests (TC-057) |
| Regression Test | TC-057 (automated, `{ todo: "BUG-003" }`), TC-062 (round-trip of special characters currently passes only for Latin-1) |
| Status | OPEN |
